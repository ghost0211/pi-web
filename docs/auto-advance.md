# 自动推进（受控 MVP）

已有会话的输入工具栏提供 **自动推进**。它不是主模型的工具循环：主模型仍照常执行工具，只有整个逻辑运行 `agent_settled` 且 RPC 收尾/主模型恢复完成后，替身模型才判断下一步。

## 使用

1. 先向主模型提交任务；在已有会话中点击自动推进。
2. 明确填写目标/验收标准、**允许继续做什么 / 遇到什么要停**，选择替身模型和独立的**替身思考档位**。
3. 设置最多追加 **1–99 轮**（默认 3 轮）；点击开始才启用。**不设总时长或总 Token 预算上限**，可能持续数小时并不断产生费用，请按需监督和停止。
4. 等待替身选择继续、完成或需要用户确认。随时停止或手动发送/引导接管。

忙碌时启用会等待当前运行完成；空闲时判断最新成功回答。没有成功回答、输出截断、判断 JSON 无效或错误时暂停，不盲目重试。轮数只统计替身追加的主模型运行，不含启用前那一轮。达到轮数上限即停止，不再额外调用替身判定完成。

## 替身思考档位

档位只控制替身判断下一步的推理，不修改主模型或额度备用模型的档位。默认为 `auto`（旧配置缺少该字段也按 `auto` 处理），由服务器按替身模型自己的 enabledModels 思考固定值、否则 SDK `medium` 默认及能力解析；不会继承主模型的档位。

下拉框按所选替身的 SDK 能力过滤，provider 原生映射只用于显示，提交仍是 `off/minimal/low/medium/high/xhigh/max` 等标准值。未知能力时只显示禁用的 `auto`；无推理模型显示禁用的 `off`。换模型保留兼容选择，不兼容则回到 `auto`。服务器还会独立拒绝不支持的显式档位。

较高档位可能增加耗时和 Token 消耗；推理 Token 已包含在 output 用量中，不再重复计数。`auto` 不保证每个模型的实际成本相同。

## 授权边界

替身调用不携带工具，不能修改主会话的模型、主/备用思考或额度备用配置。它通过现有 ModelRuntime 取得认证/自定义 provider，重新校验可用模型和 enabledModels 范围；虚拟路由模型暂不支持作为替身。

替身输出是严格 JSON，必须包含 `requiresConfirmation`。需要确认时不得继续。发送到主模型的是 `pi-web:auto-advance` **custom 消息**，不是人类 user 消息；模型可见正文明确写明 AI 来源、目标/范围以及“不构成新授权”。界面保留来源卡并将每轮处理详情分开。

“允许继续做什么 / 遇到什么要停”使用文本框，是因为每个任务的边界不同，需要你用自然语言明确说明。例如：**只修改当前项目并运行测试；不要提交、发布或删除文件。涉及这些操作先问我。** 示例只是 placeholder，不会自动填入或授予权限，字段仍然必填。它描述已有许可与必须停下确认的事项，不是勾选后解锁工具的权限开关。

**这不是权限沙箱**。主模型仍拥有会话原有工具；自然语言操作范围、风险判定依靠模型遵守，不能保证拦截每一项越权工具操作。提交、发布、破坏性删除、外发等必须有真实用户的事先明确授权；替身不能生成授权。高风险/生产操作不宜无人监督。自动判断“完成”也是模型判断，不是独立验收证明。

## 轮数、统计和生命周期

- 仅以追加轮数限制自动续跑，支持 1–99。删除旧版的时长定时器与累计 Token 熔断，不通过隐式默认值保留旧限制；旧客户端传入的 `maxMinutes`/`tokenBudget` 被忽略并从规范化配置中移除。
- Token 从启用开始累计收到的主模型 assistant、带用量的工具结果及替身用量（含缓存、不重复加 reasoning），**仅用于统计展示**，消耗超过 20000 或数百万 Token 都不会停止。用量缺失/无效时标记“统计不完整”，而非暂停工作；不完整的累计数不能当作实际总账单。
- 替身只读取最多 32 条、12000 字符的近期文本证据，排除图片、思考、工具输入和 system 提示；并非完整会话审计。替身结构化判断的请求 `maxTokens` 上限仍为 1536（受所选模型输出能力约束），这只限定简短判断响应，不是主模型回复/推理/工具工作的 Token 预算。部分 provider 的 SDK 推理适配器还会调整该次请求的推理/输出预算。模型自身上下文容量和 provider 限制仍然存在。
- 不设置自动推进总时长；单轮长时间执行不会因过去 15 分钟而被中止。用户停止会中止替身和控制器拥有的主模型运行，但不会撤销已经执行的工具副作用。
- 手动 prompt/steer/follow-up、分支/模型/思考/工具/MCP 等变更取消后续推进，不擅自中止当前主模型运行；原有忙碌限制仍然生效。
- 阻塞式扩展 UI 暂停自动推进，并保留当前确认对话框。归档也取消后续推进，保留原有正在运行的会话行为；归档/观察型子代理不能开启。
- `isRunning()` 包括替身判断/等待阶段，继续保护空闲回收、会话永久删除和替换。所有自动续跑通过原有删除变更屏障。
- 激活状态只在 wrapper 内存中；刷新/多窗口通过 RPC 状态与 SSE 观察，不能重新启用。关闭窗口不取消服务器任务；服务器重启、wrapper 销毁、切换副本不会自动恢复。重启后的历史来源卡也不能重新激活。
- 状态使用 activation id、递增 revision、异步 generation 和 AbortSignal，丢弃取消/重启后的迟到结果。每轮主模型结算仍使用现有计时/主模型恢复逻辑；完成通知只在整个自动推进完成或需要关注时发送，不每轮响铃。

## 验证范围

核心状态机、无工具替身适配、RPC 生命周期、前端来源分组和弹窗测试使用本地模拟响应。时间旅行测试覆盖 8 小时运行/判断不超时、普通 10 分钟空闲回收不终止活跃控制器；测试覆盖实际 99 次续跑与数千万累计 Token、统计缺失仍可执行有效决策，以及 Stop/人工接管/错误暂停。SDK 集成使用真实 Pi SDK 配合无网络假模型，不代表真实 provider 的费用、限流、授权判断质量或桌面后台运行的端到端验证。
