# Pi Web v0.9.39

## Pi SDK 1.0.3 compatibility

- Upgrade the four embedded Pi dependencies to 1.0.3. Updating the global CLI
  alone does not deploy a new Web build; Node.js 22.19.0 or newer is required.
- Preserve model-level `samplingParams` and `samplingParamsByThinkingLevel`,
  including `modelOverrides`, through Web edits and cost normalization. Public
  SDK types and native request merging are used; no automatic sampling tuning
  or dedicated sampling editor is introduced.
- Recognize the new Azure provider ID `azure`, while retaining the historical
  icon mapping. Credentials and provider/model/settings keys are not migrated
  automatically.

## MCP project overrides and OAuth

- Support explicitly trusted project overrides containing only `enabled`,
  `exposure` and `toolExposure`, inheriting a same-name global server's transport
  and authentication. Full project definitions still replace global entries.
- Display inherited values and submit only changed override fields. Unchanged
  saves do not enable disabled servers or erase hidden per-tool permissions;
  explicit `true` and `"codemode"` override values remain on disk.
- Validate the global base and effective merged configuration. Global dependency
  reads keep regular-file, symlink and 10 MiB protections; catalog errors do not
  reflect sensitive configuration keys or values.
- Expose `oauth.clientRegistration: "dcr" | "cimd"` in the existing JSON editor.
  CIMD forbids `clientId` / `clientName`; explicitly configured callbacks must
  use `localhost` or `127.0.0.1` with the exact `/callback` path.
- Preserve full-server transport editing, explicit save/reload, trust boundaries,
  secret masking and unknown private fields. Config editing never connects a
  server or starts a session; native maintenance actions require a live session
  and an available, enabled effective server.

## Generated images and subscription safety

- Carry the source session ID through chat Markdown local-image requests and
  reuse the same file URL helper as FileViewer. SDK Codemode temporary images
  remain readable only through existing exact-session-file authorization, not
  a blanket `/tmp` permission. Markdown URL sanitization stays unchanged.
- Verify actual SDK-generated image bytes, POSIX `0600` permissions and cleanup.
  Standard image previews and once-only usage accounting remain unchanged.
- Add synthetic Codex/Kimi subscription regressions for read-only listing,
  cancellation-safe token rotation and reuse without duplicate refresh. These
  exercise the official SDK with temporary credentials; they do not certify
  real-provider login or establish the cause of a prior subscription failure.
- This release does not perform CLI update/login/logout or replace subscription
  credential files.

## Verification

- 1345 tests; type checking, zero-warning lint and whitespace checks.
- Fresh isolated regular and standalone builds, with 30 HTTP checks each.
- Six built-bundle asset guards, six public runtime imports and 15 actual
  standalone SDK fixtures covering images, MCP and loopback OAuth.
- Tests and HTTP servers use temporary HOME/agent directories and synthetic or
  local providers, not production credentials or paid model calls.

Existing export-route dynamic-import warnings remain. Browser/WebView and
real-provider authentication are outside the fixture certification; arbitrary
stdio MCP executables must be installed on the server's PATH.
