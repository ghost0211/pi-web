# Pi Web v0.9.40

## Embedded Pi SDK 1.0.4

- Upgrade the four embedded Pi dependencies to 1.0.4. The Web SDK and global CLI
  are separate installations; this service deployment does not update the CLI.
- Codemode can pass an image returned by `tools.read()` directly to `image()`.
  Existing standard-image rendering, private saved files and exact-session-file
  authorization remain in use; no blanket temporary-directory access is added.
- Inherit the upstream QuickJS builtin freezing and settled-result protections,
  and the prompt-guideline fixes for hidden tool declarations.
- Inherit MCP native-client dynamic registration and cleanup of transports that
  are still connecting at shutdown, using the existing official MCP bridge.
- Preserve exact Web tool selection, exposure, Chat-only and subagent resource
  restrictions. CLI wildcard patterns and `--no-mcp` do not introduce new GUI
  controls or silently alter Web presets.

## Fix Settings → Update CLI failing with EEXIST

- Locate the active Pi launcher and its actual npm global installation instead
  of assuming that the npm on PATH owns the same installation prefix.
- Validate the package name, manifest `bin.pi`, entrypoint and platform layout,
  and explicitly pass the verified prefix to npm. Nested hand-created launcher
  aliases remain unchanged; no `--force`, deletion or automatic migration is used.
- Reject unrecognized wrappers, source-linked packages, pnpm/npx layouts and
  invalid metadata with an original-installation-method hint.
- Check supported Windows npm `.cmd` shims against their real entrypoint and
  reject unsafe shell characters. Native Windows operation is not certified by
  the filesystem simulations alone.
- Do not report CLI update success solely because npm exited zero: the active
  CLI version must also be verifiable. Local SDK update behavior is unchanged.
- The `node-domexception` deprecation warning is not the EEXIST failure cause.

## Safety and validation

- Regression coverage uses temporary HOME/PATH/agent directories, synthetic
  providers and fake npm executables. Image and MCP OAuth fixtures exercise the
  actual SDK without production credentials or paid model calls.
- Original-source EEXIST reproduction, launcher preservation and post-update
  CLI verification are tested; subscription read-only listing and cancellation
  regressions remain in the suite.
- Service rollout retains the previous `.next` and `node_modules`, waits for
  running sessions to become idle, and checks versions, build identity, model
  providers and HTTP health. Failure restores both retained directories.
- This deployment performs no global CLI update, login/logout, credential
  replacement or Azure-provider migration. Node.js >=22.19.0 remains required.

## Verification

- 1376 Linux/offline tests; type checking, zero-warning lint and whitespace checks.
- Fresh isolated regular and standalone builds, with 32 HTTP checks each. The
  compiled updater is exercised with a synthetic CLI/npm installation, checking
  the exact prefix, unchanged outer alias and the actual resulting CLI version.
- Six bundled-asset guards, six public runtime imports and 19 actual standalone
  SDK fixtures, including image reads, sandbox freezing and native-client DCR.
- Current npm audit findings match the SDK 1.0.3 baseline: 20 findings (6 low,
  4 moderate, 10 high), no critical findings or newly introduced package keys.
  This release does not attempt broad unrelated dependency remediation.

Existing export-route dynamic-import warnings remain. Native Windows execution,
WebView behavior and real-provider authentication are outside fixture certification.
