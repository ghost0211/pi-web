# Pi Web v0.9.41

## Fix desktop session-list HTTP 500 after upgrades

NSIS `/UPDATE` previously overlaid the new resources without removing packages
that disappeared or moved in the newer dependency layout. Upgrading from Pi
SDK 0.99 to 1.0 could leave a nested `pi-tui` 0.99.1 alongside the new hoisted
SDK 1.0.3. Node loaded the obsolete nested package first, causing
`setImageTranscoder` import errors and HTTP 500 on the session-list API.

- Stage old generated `server/` and `node/` directories as `server.previous`
  and `node.previous` before installing fresh payloads, after checking the
  running application. Old files can no longer shadow new dependencies.
- If staging Node.js fails, restore the server directory before aborting so
  both old payloads remain usable. Failed staging returns a nonzero exit code.
- Remove backups only after copying the new payloads. Never overwrite recovery
  copies from an interrupted installation; retain locked backups outside the
  live runtime paths for manual cleanup/recovery.
- Preserve the installation root, user sessions, credentials, Desktop settings
  and browser-local preferences. Keep missing desktop-shortcut recovery.

## Verification and CI

- Real NSIS regressions cover fresh installation, reinstallation, `/UPDATE`,
  locked server/Node.js directories with both old payloads present, rollback
  usability and existing recovery-copy protection.
- Full Web tests, type checking and lint run on Ubuntu. Windows runs Rust shell
  tests and mandatory compiled NSIS regressions before publishing the signed
  installer; a missing NSIS compiler fails instead of skipping these checks.
- The npm manifest, lockfile root and Cargo manifest/lockfile are synchronized
  to 0.9.41. Desktop releases remain signed, with immutable version tags.
