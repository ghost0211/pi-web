# Pi Web v0.9.46

## Unified session management

- Replace overlapping hidden/archive states with normal and archived sessions.
  Settings → Sessions and the sidebar management entries provide the complete
  catalog, search, lifecycle/project filters and bulk operations. Opening an
  archive is read-only; restoring it is explicit and makes its project visible.
- Keep project visibility separate: removing a project from the sidebar does
  not archive sessions, close the selected chat or delete project files. Bulk
  project archiving is a distinct action. Pins apply only to normal sessions.
- Store Pi Web metadata under `getAgentDir()/pi-web/`, shared across windows,
  rather than rewriting SDK conversation files or `settings.json`. Back up
  exact legacy browser values locally and on the server before importing them;
  keep the old keys unchanged and preserve explicit restoration decisions.
- Archived chats preserve running-session observation, completion notifications,
  stop/abort and extension responses while disabling sends, editing and forks.
  Drafts remain saved. Subagent panes remain observational.
- Add English, Simplified Chinese and Traditional Chinese management labels.

## Safe permanent deletion

- Require explicit confirmation, delete sequentially and report each result.
  Failed rows remain visible; metadata-cleanup warnings do not misreport a
  successfully deleted session as still present. Confirmed deletions propagate
  across windows, including sessions with no explicit metadata record.
- Reject busy targets, startup/mutation conflicts and loaded direct dependents
  with 409; never implicitly abort children. Protect SDK startup and mutating
  commands with hot-reload-safe per-session barriers. Discover loaded children
  from headers/subagent metadata even before their first JSONL flush.
- Preserve direct child conversations by reparenting them with atomic writes
  and attempted rollback on failure. Delete only the selected session file;
  project files and descendant conversations are not recursively deleted.
- Cross-process locks serialize DELETE requests, but do not share registries
  or coordinate external Pi CLI writes. Unpersisted children in another Node
  process cannot be discovered. Idle loaded children are conservatively refused
  until unloaded. See [the architecture decision](../adr/0005-unified-session-management.md).

## Verification and desktop delivery

- Local release checks: 288 focused regressions passed, including compiled
  NSIS upgrade/rollback tests; six platform-specific tests skipped on Windows.
  All five Rust shell tests, typecheck and repository-wide zero-warning ESLint
  pass. Isolated Next API smoke checks verified immutable legacy backups, unchanged
  fixture JSONL hashes during migration/archive/project removal, confirmation
  enforcement, target-only deletion and retained/reparented child messages.
  No original user sessions were migrated or deleted during verification.
- Browser foreground verification was blocked by the Windows focus restriction;
  interaction checks used deterministic component harnesses. Ubuntu full Web
  tests, Windows Rust tests, signed packaging and mandatory compiled NSIS
  installation/rollback checks gate desktop publication.
- Synchronize npm/Cargo manifests and lockfiles to 0.9.46. Publish a fresh signed
  installer and updater manifest under immutable tag `desktop-v0.9.46`.
  Keep the embedded Pi SDK 1.1.0 and staged installer payload replacement.
