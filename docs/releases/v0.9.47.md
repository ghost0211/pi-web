# Pi Desktop / Pi Web v0.9.47

## Desktop appearance and tray shortcuts

- Use **Pi Desktop** for the desktop sidebar, new-session screen, About page,
  native window and tray. Ordinary browsers retain **Pi Web**. Keep the existing
  **Pi Web Desktop** installer identity, Start Menu entry, installation directory
  and updater asset naming so existing installations upgrade normally.
- Localize the tray in English, Simplified Chinese and Traditional Chinese.
  Add New session and the three most recently modified normal conversations;
  archived sessions and subagents are excluded. Explicit tray actions wait for
  migration, confirmed session operations and project-trust dialogs rather than
  interrupting them. Focus or notifications alone never change the selected chat.
- Keep recent session IDs and titles in memory only. Persist only translated
  labels and locale for startup; serialize atomic settings writes, preserve
  unknown fields, refuse symlink replacement and fail closed on corruption.
- Show the actual desktop installation directory in About and diagnostics,
  separately from the server's runtime working directory.
- Improve monochrome provider icon contrast in both light and dark themes while
  preserving colored brand accents and custom-provider fallbacks.
- Separate the session-management Refresh and Close controls, with dedicated
  action spacing and responsive layout.

## Chat images and compaction navigation

- Display message images as uniform thumbnails above and outside the user text
  bubble: 160 x 108 on desktop and 112 x 80 on mobile, with wrapping and the
  original full-image preview. Image-only messages no longer create empty bubbles.
- Remove compaction summaries such as `Goal` from the chat navigation rail.
  Summaries remain in readable history; only user prompts create navigation
  anchors. Post-compaction answers stay with their current user turn, and paging
  placeholders are used only for scroll alignment, never as clickable nodes.

## Clearer subagent reports and parent follow-ups

- Render subagent conclusions and reviews as separate, initially collapsed
  report cards with source, short task description, profile, status and completion
  time. Expanding retains the complete Markdown and file links; valid session IDs
  provide an entry to the child conversation. Existing reports remain readable.
- Preserve arrival order and group adjacent reports before the parent's follow-up.
  Label subsequent parent replies separately instead of folding the original
  main reply into process details or treating the supplemental reply as its replacement.
- Add model-visible provenance and integration guidance to **new** notifications
  so the parent can correlate parallel tasks and focus on new findings instead
  of repeating a full report. Store raw report text separately for UI rendering;
  internal integration instructions are not shown in report cards.
- Do not rewrite existing conversation files or reorder old messages. Automatic
  follow-up delivery remains the SDK's existing behavior.

## Verification and delivery

- Local release checks: **400 focused regressions passed**, with six
  platform-specific tests skipped on Windows. All **10 Rust shell tests**,
  TypeScript and repository-wide zero-warning ESLint pass. Real compiled NSIS
  fresh-install, reinstall, update, staging rollback and recovery-copy protection
  checks pass. Isolated browser fixtures checked thumbnail sizing, report
  expansion and narrow-screen overflow without using real sessions.
- Full Web tests run on Ubuntu CI. Windows CI also tests the Rust shell and
  requires real compiled NSIS upgrade/rollback checks before publication.
- Publish a fresh signed installer, detached signature and `desktop-latest.json`
  under immutable tag `desktop-v0.9.47`; keep the embedded Pi SDK at 1.1.0.
  CI uses these curated notes when available and publishes the update feed only
  after all signed assets have uploaded.
