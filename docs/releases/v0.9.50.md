# Pi Desktop / Pi Web v0.9.50

## Independent primary and backup thinking levels

- The composer now shows one reasoning menu per model. The backup menu lists
  only levels that backup model supports and uses its provider-native labels.
- While no backup model is configured the backup menu stays visible but gray,
  disabled, and unopenable, with an explanation instead of a silent no-op.
- Capability data that has not loaded yet, models without adjustable reasoning
  (only `off`), busy sessions, and read-only views also disable the menu with a
  visible reason. Changing a model, starting a run, compacting, or switching
  models closes an open menu so a stale click can never apply the old model's
  level.
- The backup's level is stored atomically with its model reference and defaults
  to the backup model's own default. Changing primary thinking never rewrites
  it, and changing it never touches the active session's thinking level. Legacy
  configurations without a level stay valid and mean "use this model's
  default". Clearing the backup clears its level.
- Quota failover now applies the backup's own level explicitly after switching
  models and before continuing the run, instead of inheriting the primary
  session's level (the SDK clamps a single session-level thinking state, so
  primary and backup preferences cannot share one). Unsupported legacy choices
  fall back to the backup model's default, and non-reasoning models resolve to
  `off`.
- Switching the primary model no longer leaks the previous model's draft level
  into a new session, and a failed switch restores the previous model and level.

## Upstream priority port (security, correctness, stability)

Ported the highest-value upstream fixes onto this fork's architecture rather
than merging upstream `main` (98 conflicting paths and divergent MCP, subagent,
sidebar, and auth designs).

- **Configuration safety** — an unreadable `models.json` now fails loudly
  instead of reading as empty: `GET /api/models-config` answers `422`, `PUT`
  answers `409`, and the panel disables saving so a blank draft can never
  overwrite the file. BOM, `//` comments, and trailing commas are tolerated the
  same way pi's loader tolerates them.
- **File authorization** — file paths are no longer trusted from system
  messages, context edits, codemode stores, or the text of non-coding tool
  results; only coding/subagent results, spilled full-output paths, and real
  nested coding calls authorize a path.
- **Windows and CLI** — restored drive roots (`D:`), preserved UNC roots through
  API encoding, normalized plugin `relativePath` separators, and moved npm/npx
  invocation to the bundled Node CLI scripts, which avoids `npm.cmd`
  `spawn ENOENT` and never needs a shell.
- **Authentication and command environment** — manual OAuth handshakes use
  `crypto.randomUUID()`, `PI_WEB_PASSWORD` is stripped from agent command
  environments, and repeated Basic Auth failures now share an exponential
  backoff with `Retry-After` (desktop health nonce exemption preserved).
- **Uploads, service worker, and shutdown** — raised the proxy body buffer to
  128 MB for the 100 MB upload route, bounded service-worker navigation/asset
  waits so a dead upstream falls back to the offline page without truncating
  streamed responses, and closed live SSE streams on `SIGINT`/`SIGTERM` so
  Next 16's connection drain can no longer strand a zombie process. The Node
  signal hook lives in `instrumentation-node.ts` so the Edge instrumentation
  graph stays free of Node APIs.
- **Slow clients** — SSE backpressure now drops rebuildable deltas, keeps block
  boundaries and authoritative content, terminates a stream whose backlog
  exceeds the limit so the client reconnects and re-snapshots, and isolates
  subscriber failures from other listeners on the same session.
- **Session lifecycle** — a closing wrapper refuses new commands, extension
  binding and `session_shutdown` share one finite cleanup deadline, reopening
  waits for real SDK disposal and coalesces concurrent restarts, and a stale
  pre-hot-reload callback can no longer unregister its replacement. Stop keeps a
  bounded fallback deadline even when idle reaping is disabled, and closing
  sessions still block permanent deletion.
- **Models and history** — opening a provider no longer force-writes
  `openai-completions`, stale `enabledModels` glob warnings are suppressed when
  other patterns still match, session tail budgets count visible messages (with
  a raw-entry cap) so tool-heavy sessions no longer starve user prompts out of
  the window, and header turns whose anchor is on an earlier page still fold
  their process details.
- **Chat correctness** — context usage refreshes after every assistant message,
  output-limit truncation is surfaced, an unanswered truncation offers
  compaction instead of another retry, read-only views hide mutation actions,
  process details auto-collapse once an answer exists without duplicating the
  terminal notice, and deleting a session the user already navigated away from
  no longer forces an empty chat.
- **Compaction usage display** — after a compaction that has no new assistant
  usage yet, the SDK reports `tokens: null`; the server previously reused the
  pre-compaction usage of a retained message. Usage now reflects the estimated
  post-compaction context (including native system/checkpoint and summary
  entries) and ignores retained pre-compaction usage, so the ring updates
  immediately instead of waiting for the next turn. Stale poll and file
  estimates can no longer overwrite newer SDK usage.
- **Dependencies and CI** — Next.js and `eslint-config-next` 16.3.8, with
  non-forced audit fixes applied and the Pi SDK kept at 1.1.0. Web and desktop
  CI pin Node 22.19.0.

## Deliberately not adopted

- No wholesale upstream merge; MCP modernization and the large subagent
  queue/resume/worktree work remain separate projects.
- The upstream change that stops persisting an explicit new-session model choice
  contradicts this fork's documented startup-preference behavior, so explicit
  new-session selections are still persisted.
- No browser cookie-login migration, sidebar redesign, or upstream
  release/version commits.

## Verification and delivery

- Full local suite: **1699 tests, 1667 passed, 28 skipped, 4 failed**. All four
  failures are the pre-existing Windows `EPERM` fixture limitation where MCP
  security tests cannot create symlinks, so their assertions never run. Linux CI
  covers those paths.
- `tsc --noEmit`, repository-wide zero-warning ESLint, and `git diff --check`
  pass. `npm audit --omit=dev` reports 0 vulnerabilities; the full dev-inclusive
  audit still reports 13 advisory entries whose suggested fixes are breaking
  upgrades or downgrades, so none were forced.
- Publish a fresh signed installer, detached signature, and
  `desktop-latest.json` under immutable tag `desktop-v0.9.50`, keeping the
  embedded Pi SDK at 1.1.0. The release becomes latest only after every signed
  asset has uploaded.
