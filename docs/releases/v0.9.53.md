# Pi Desktop / Pi Web v0.9.53

## Quota fallback now catches Codex in-stream limit errors

- Codex reports subscription exhaustion as an SSE/WebSocket `error` event over
  HTTP 200, so no HTTP status/body evidence ever existed and the flattened
  message ("Codex error: The usage limit has been reached") matched no
  classifier rule. Quota fallback was skipped by design and the run settled
  with the raw error — and auto-compaction then failed against the same
  exhausted model. This was observed in real sessions on v0.9.51.
- The observer now captures the thrown error's machine code
  (`CodexApiError.code`, e.g. `usage_limit_reached`) as bounded, normalized
  evidence and the classifier treats it like a response-body code.
- The terminal in-stream phrasing "usage limit has been reached" is also
  accepted, scoped to OpenAI-family providers (pi-ai itself treats it as
  non-retryable). The friendlier "You have hit your ChatGPT usage limit" text
  deliberately stays unclassified because pi-ai generates it for transient
  429/`rate_limit_exceeded` responses too.
- Classification remains quota-only and conservative: transient throttles,
  unknown codes, other providers and non-string codes still return `null`, and
  fallback still runs at most once per logical run with the v0.9.52
  restore-primary behavior unchanged.

## Verification and delivery

- New classifier cases plus an end-to-end runtime test drive an HTTP-200
  in-stream failure into a one-time backup switch; the fallback cluster passes
  71/71 locally, and TypeScript + zero-warning ESLint are clean.
- Publish the signed installer, detached updater signature and
  `desktop-latest.json` under immutable tag `desktop-v0.9.53`. The release
  becomes latest only after all three assets upload. Pi SDK remains 1.1.0;
  this release changes no dependency versions.
