# Pi Desktop / Pi Web v0.9.55

## 自动推进（Auto Advance）

- New **自动推进** entry in the composer toolbar. It is a controlled MVP: after
  the main model settles, an optional tool-less surrogate model decides whether
  to continue, finish, or ask the user.
- The dialog requires an explicit goal/completion criteria and an
  already-authorized operation scope, a surrogate model, and three limits —
  additional rounds (1–5), minutes (1–15) and a token budget (1,000–20,000).
  Nothing starts until the user presses start; the preference is never
  persisted and never resumes after a restart.
- Continued rounds are sent as `pi-web:auto-advance` **custom** messages with
  `triggerTurn`, never as user messages, and the model-visible text states that
  AI-generated continuation is not new user approval. The surrogate runs
  through the existing model runtime with no tools and cannot change the main
  model, thinking level, or quota backup. The history card is labelled
  **替身消息 · 非用户授权**.
- Fail-closed boundaries: missing token usage, invalid decision JSON, request
  errors, aborts, a repeated instruction, a blocking extension dialog,
  archiving, manual prompting/steering, or a configuration change pause or stop
  advancement instead of retrying blindly. Rounds run through the existing
  mutation guard, so the deletion barrier and idle reaping still apply, and
  only the terminal outcome raises one completion notification.
- The capability is bounded by design: the stated scope is model guidance, not
  a permission sandbox, so commits, releases, destructive deletion and other
  consequential actions still require the user's own explicit authorization.

## 运行耗时（Run duration）

- Completed logical runs now show their duration in **处理详情**, and the
  running-task board shows a live timer. The duration is measured server-side
  with a monotonic clock, covers the whole logical run (preparation, retries,
  tool iterations and compaction), and is stored as an invisible
  `pi-web:run-timing` entry bound to the run's final assistant answer, so it
  survives reloads, pagination and branch switching.
- Historical sessions without timing fall back to explicitly labelled
  estimates (**本轮耗时约 …**), and a missing live start hides the duration
  rather than inventing one.

## 从此处编辑（Edit from here）

- The action no longer disappears when the preceding transcript slot is a
  system, compaction or report card instead of an assistant message. Anchors
  now resolve to the nearest preceding entry while still refusing to truncate
  an unrelated earlier turn. Replaying recent sessions recovered 39 previously
  missing anchors (139/178 → 178/178) with no regressions.

## About 更新检查

- The desktop and kernel/runtime update checks now share one **检查更新**
  button at the upper right of the app hero card. One press checks both
  sources, each failure stays independent, and the separate installation
  targets, confirmations and progress states are unchanged.

## Verification and delivery

- Full local suite: **1859 tests, 1827 passed, 28 skipped, 4 failed**. The four
  failures remain the existing Windows `EPERM` limitation in MCP symlink
  fixtures; the release workflow runs the full Web suite on Linux where they
  pass.
- TypeScript, repository-wide zero-warning ESLint, and `git diff --check`
  pass.
- A real React browser fixture exercised the auto-advance dialog inside the
  real composer in zh-CN/en/zh-TW at 320px, 390px and desktop widths, covering
  autofocus, Escape/focus restore, validation, start, active and stop states
  with no horizontal overflow. Run timing was verified against the real Pi SDK
  with a no-network fixture model; no live provider billing or desktop
  installation was exercised.
- Publish the signed installer, detached updater signature and
  `desktop-latest.json` under immutable tag `desktop-v0.9.55`. The release
  becomes latest only after all three assets upload. Pi SDK remains 1.1.0;
  this release changes no dependency versions.
