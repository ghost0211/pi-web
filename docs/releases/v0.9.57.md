# Pi Desktop / Pi Web v0.9.57

## Pi SDK 1.2.0

- The four embedded Pi SDK packages are synchronized to **1.2.0**. Updating the
  global Pi CLI no longer risks leaving Web or the next desktop bundle on SDK
  1.1.0.
- SDK 1.2 custom-run lifecycle is covered for user and extension-triggered
  turns: preparation remains busy, queued custom messages are not fabricated as
  user prompts, and forced system prompts survive a tool follow-up.
- OpenRouter personalized `/models/user` catalogs, regional endpoints, limits
  and prices flow through the existing shared model scope; offline cached
  catalogs remain supported. Configuration `$schema` and unknown root metadata
  survive `models.json` round trips.
- MCP status redaction and desktop package validation were rechecked against
  SDK 1.2. The removed `chord` package stays supported in legacy desktop
  validation fixtures without being reintroduced.

## Quota fallback

- Fixed a real incident where a configured backup model was not used after a
  Codex quota error. SDK automatic compaction shares the same stream adapter;
  it previously cleared the finalized main answer's quota evidence before the
  fallback boundary ran.
- The finalized main failure now owns its bounded request evidence. Later
  compaction or summary calls cannot erase it or lend their quota errors to a
  non-quota main error. The classifier remains quota-only, context/image
  validation and failed-entry exclusion stay intact, and the configured primary
  model/thinking level is restored after settlement.
- Real-SDK no-network regressions cover both user turns and extension-triggered
  follow-ups with automatic compaction enabled. Prompts are never resent and
  tools are never replayed.

## Auto Advance

- The surrogate has an independent thinking-level selector. Options are filtered
  by the selected surrogate's capabilities, provider mappings are display-only,
  and the server submits the canonical level. It never reads or mutates the
  primary or quota backup's thinking preferences.
- The confusing “authorized scope” field is now labelled **what to continue /
  when to pause**, with explicit help and examples. It remains required, empty
  by default, and is clearly documented as guidance rather than a permission
  toggle or sandbox.
- Time and aggregate Token budget limits are removed. Only additional rounds
  are limited, now **1–99** with the existing default of 3. Reported usage is
  shown for supervision; missing or invalid usage marks the total incomplete
  instead of pausing an otherwise valid decision.
- Stop remains available during startup and active runs. Manual takeover,
  configuration changes, extension prompts, repeated instructions, run errors
  and lifecycle barriers still stop or pause advancement. Long-running work may
  continue for hours and incur ongoing provider costs; supervise it and stop it
  explicitly when needed.

## Verification and delivery

- **176 focused tests passed**. Full local suite: **1906 tests, 1874 passed,
  28 skipped, 4 failed**. The four failures remain the existing Windows
  `EPERM` limitation in MCP symlink fixtures; release CI runs the complete Web
  suite on Linux.
- TypeScript, repository-wide zero-warning ESLint and `git diff --check` pass.
- Real React browser fixtures passed at **320/390/1440px in zh-CN/en/zh-TW**
  plus a reduced 390×440 viewport, covering 1–99 round validation, independent
  thinking selection, mapped labels, required scope, partial usage display,
  focus restoration, Stop during busy/pending start, real `ChatInput` payload
  passthrough and no horizontal overflow.
- Controller and real-SDK tests execute all 99 rounds with tens of millions of
  reported Tokens, simulate eight-hour main/surrogate work without a deadline or
  idle reaping, and preserve explicit Stop behavior. No live provider billing,
  physical-phone keyboard/safe-area or installed-desktop E2E was exercised.
- The signed installer, detached updater signature and `desktop-latest.json`
  are delivered under immutable tag **desktop-v0.9.57**. The release becomes
  latest only after all three assets upload.
