# Pi Desktop / Pi Web v0.9.58

## Steering messages marked, no longer treated as turns

- Messages sent with the **引导 / Steer** button while the agent is running now
  render as compact marked chips instead of full user prompt bubbles. The chip
  carries the steer badge, the original text (with image thumbnails when
  attached) and an explanatory tooltip, and it offers no fork/edit prompt
  affordances. While the run is live the chip appears inline in chronological
  position; after completion it remains inspectable inside the run's process
  details.
- Steering deliveries **no longer start a new conversation turn**: the ongoing
  run stays one prompt group, and its final answer — including work done after
  the steering injection — remains attached to the original prompt.
- Steering deliveries **no longer appear in the turn rail** (quick navigation).
  The server-side whole-branch index and the client's window-derived fallback
  both exclude them, so rail nodes are exactly the genuine user prompts.
- Pi persists steered messages as plain user entries with no marker field, so
  detection is structural and identical live and after reload: a run stays open
  after an assistant turn with tool calls (unless it aborted or errored —
  abort-synthetic “Operation aborted” tool results never reopen it) and closes
  on a completed answer or a standalone `!` bash execution. A prompt sent right
  after stopping a run is therefore never misclassified, and consecutive
  steering messages or mid-run auto-compaction stay attributed to the open run.
  The documented approximation: a steering message drained after the run's
  final answer is structurally indistinguishable from a fresh prompt and
  remains a normal turn. Follow-up queue deliveries keep starting genuine new
  turns by design.
- Full-history marking walks the raw branch, so even a lazy-loaded window that
  starts exactly at a steering message is marked correctly.

  fixtures; release CI runs the complete Web suite on Linux.
- TypeScript, repository-wide zero-warning ESLint and `git diff --check` pass.
- Real React browser fixtures passed in **zh-CN / en / zh-TW**, covering chip
  rendering with badge and hint, absence of prompt affordances, single-turn
  grouping, rail exclusion on both the server index and client fallback, and
  collapsed/expanded process-detail rendering.
- The signed installer, detached updater signature and `desktop-latest.json`
  are delivered under immutable tag **desktop-v0.9.58**. The release becomes
  latest only after all three assets upload.
