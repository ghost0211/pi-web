# Pi Desktop / Pi Web v0.9.59

## Usage & cost dashboard: filter by provider and model over any period

- The **用量与成本 / Usage & Cost** settings panel is now a dashboard instead of
  a single all-time snapshot. A filter bar offers **全部时间 / 今天 / 近 7 天 /
  近 30 天 / 自定义** (all time / today / last 7 days / last 30 days / custom),
  and the custom option takes an explicit from-to date range. The applied range is
  shown next to the project scope, and every number on the panel — summary cards,
  trend, providers, projects — reflects only the selected period.
- **New per-provider breakdown** with a token-share bar and nested model rows,
  replacing the flat all-model list. Each provider row shows tokens (with the
  share of the filtered total), requests, sessions and cost; the models beneath
  it keep the cost-descending order and the full `provider/model` key in the
  title.
- **New token trend chart**: a CSS-only bar per calendar day, automatically
  merged into `YYYY-MM` months when the period spans more than 92 days. It is
  exposed as a single accessible image with a textual summary, and every bar
  carries its exact token and cost values in a tooltip.
- Time periods are resolved in the **browser's timezone**: the panel sends
  client-local `YYYY-MM-DD` bounds plus the browser's `getTimezoneOffset()`
  minutes, so a record is bucketed by the user's own calendar day rather than
  UTC.
- Server-side, each parsed session now caches compact timestamped usage samples
  alongside its aggregate, so switching between periods reuses a single parse
  instead of rescanning files. Cost is still summed verbatim from what each
  session recorded — never recomputed from a price catalog.
- Usage records whose entries carry no usable timestamp keep contributing to
  all-time totals, but are excluded from a ranged query and reported explicitly
  (never guessed into a bucket), so a filtered view cannot silently invent
  figures.
- Validation and privacy are unchanged in spirit: malformed dates, impossible
  calendar dates such as `2026-02-30`, an inverted `from`/`to` order and an
  out-of-range timezone offset are rejected with a static 400, scope parameters
  are never echoed back, and the payload still carries basename-only project
  names with 12-character hashed ids. Resource bounds and skip reasons remain
  visible through the existing partial-scan banner.

## Verification and delivery

- Full local suite: **1932 tests, 1900 passed, 28 skipped, 4 failed**. The four
  failures remain the existing Windows `EPERM` limitation in MCP symlink
  fixtures; release CI runs the complete Web suite on Linux.
- TypeScript, repository-wide zero-warning ESLint and `git diff --check` pass.
- New server coverage: timestamped record emission (including message-timestamp
  fallback and the no-timestamp case), range filtering with the echoed range,
  provider grouping with nested models, timezone-correct day buckets, month
  merging beyond 92 days, untimestamped handling, cross-range cache reuse, and
  strict parameter parsing. The API route is driven end to end for both the
  invalid-date 400 and a ranged query.
- Real React browser fixtures passed in **zh-CN / en**, covering the initial
  all-time render, the preset filters (request parameters verified, including
  the `tz` offset), the custom date range, the trend chart, the provider share
  bars and the nested model rows.
- The signed installer, detached updater signature and `desktop-latest.json`
  are delivered under immutable tag **desktop-v0.9.59**. The release becomes
  latest only after all three assets upload.
