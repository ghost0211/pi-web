# v0.9.64

## 本轮成果：支持识别并核实命令生成的交付文件

当本轮通过运行脚本或命令行（如 `python work/build.py` 生成 `sql/V1...__Init.sql`）产出文件时，原本的「本轮成果」卡片只记录被 `write`/`edit` 写入的脚本文件，用户真正关心的产出物却无法出现在卡片里。此外，Windows 会话的 `powershell` 工具调用此前也被漏记在命令历史之外。本次修复：

- **命令记录支持 PowerShell**：与 Bash 享有完全相同的命令状态、退出码与输出展示，Windows 会话的命令折叠条恢复可见。
- **回答声明候选提取**：从助手回答的行内代码段提取具有路径特征的候选交付文件（过滤 URL、CLI 旗标、无扩展名短语，自动排除已落盘的改动文件，数量上限 12）。
- **时间戳安全核实**：回答声明**不作为独立凭据**。客户端通过 `/api/files?type=meta` 核实每个候选文件的真实存在与修改时间（`mtimeMs`），必须落在当前轮次的时间窗口内（以用户消息时间戳为基准，带 120 秒时钟偏差容差）。历史遗留文件、规范引用等未在当前轮次被修改的文件**自动静默排除**。
- **独立「命令生成」标签**：通过核实的文件显示在专属的「命令生成」标签下，与「改动的文件」并列，同样支持点击在右侧查看器打开和 Git Diff 对比。

### 验证

- 全量 1970 测试：1938 通过 / 28 跳过 / 仅 4 个已知 EPERM（Windows 符号链接）；tsc / lint 干净。
- 真实业务场景（浦东数据稽核单据生成：Python 脚本写在先、PowerShell 跑脚本生成 260KB SQL 在后）端到端浏览器复现验证：卡片同时显示改动的 Python 脚本、命令生成的 SQL 文件，旧规范参考文件被正确过滤。
