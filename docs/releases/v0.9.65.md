# v0.9.65

## 子代理结果改为「按需拉取」，不再自动推送完成报告

后台子代理完成时，以前会**无条件**向主会话注入一条报告（`pi-web:subagent-notification`），并以 `triggerTurn: true` **强制开启一轮新模型回合**——即使主模型在当轮已经通过 `get_subagent_result` 读到了同一份结果（这正是工具指南要求它做的事）。

在一个真实会话上实测出两笔开销：

- **8 条通知 → 8 轮空转回合**：被强制说话的主模型只能复述「没有新增结论，以上一条为准」。
- **上下文永久膨胀**：自定义消息的内容会被转换成 `role: "user"` 消息，因此整份报告文本会留在会话上下文里，之后**每一次请求重复计费**，直到被压缩清掉。8 条通知共 34,727 字符（≈10,900 tokens）。

本次改为：

- `SubagentExtensionRuntime` 移除 `notifyParent`，运行时**在类型上就无法**再向父会话注入报告。
- 后台 `Agent` 的工具返回明确说明「不会自动投递」，并要求调用 `get_subagent_result`（`wait: true`）。
- `Agent` 的工具指南把「定稿前必须逐个拉取结果」写成硬性要求。
- 仍保留对完成事件的观察，晚到的失败不会变成未处理的 Promise 拒绝。

### 兼容性

历史会话里**已经持久化**的报告卡片照常显示（`SubagentReport.tsx`、`parseSubagentReport`，以及 `lib/chat-message-groups.ts` / `lib/run-duration.ts` 中的分组分支均保留）——仅停止产生新报告。

### 取舍

若模型始终不主动拉取结果，结果将只存在于子代理会话中，需手动打开查看。实测使用中模型 6/6 都会 `wait: true` 轮询，该契约现在也由工具文案与指南明确要求。

### 验证

- 全量 1970 测试：1938 通过 / 28 跳过 / 仅 4 个已知 EPERM（Windows 符号链接）；tsc / lint 干净。
- 测试更新为新契约：后台调用绝不产生自定义消息、工具指南必须要求轮询、真实 controller 的 `extensionRuntime` 键集合必须为 `["get","start","steer"]`。
