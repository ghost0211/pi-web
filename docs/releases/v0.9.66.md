# v0.9.66

## 选择目录对话框支持「新建文件夹」

以前只能浏览已有目录——想开一个新项目就得先关掉对话框、在别处建好文件夹再找回来。现在对话框底部左下角有 **「新建文件夹」** 按钮：展开一行内联输入，输入名称后点「创建」，**直接进入新建的目录**，接着点「选择此文件夹」即可。Esc 可取消输入行，名称为空时「创建」禁用。

### 服务端 `POST /api/cwd/mkdir`

`{ parent, name }` → 只创建**一个**叶子目录并返回规范路径：

- **绝不隐式创建缺失的父目录**（普通 `mkdir`，非 `recursive`）——打错字不会静默生成一串目录
- **绝不覆盖**已存在的同名目标，返回 `409`
- 只接受**叶子名**：路径分隔符、`.`/`..`、盘符前缀、控制字符、Windows 非法字符（`< > : " | ? *`）、系统保留设备名（`CON`、`NUL`、`COM1`、`LPT9`、`aux.txt` 等）、超长名称、以及在 Windows 上以点或空格结尾的名称，全部拒绝——名称无法逃逸出它被输入的那个父目录
- 要求 JSON Content-Type；沿用 `proxy.ts` 的全局 API 守卫（来源 / 主机 / Basic Auth）
- 创建**不**调用 `allowFileRoot()`：新目录只有在你点「选择此文件夹」经 `/api/cwd/validate` 后才成为可浏览根，与现有安全模型一致

### 交互细节

- 拒绝原因按服务端错误码显示**本地化提示**，不泄露原始报错
- 导航到其它目录会**丢弃**未提交的名称，避免在非当前显示的目录里误建

### 验证

- 新增单元/路由用例 14 个：遍历与分隔符拒绝、非法字符、保留设备名、超长、父目录缺失或为文件、同名冲突、Content-Type 守卫、平台差异（尾部点仅在 win32 拒绝）
- 浏览器端真实交互 6 项全过：打开输入行并自动聚焦 → `../evil` 被拒且不导航不改列表 → 同名冲突提示 → 创建后进入新目录（服务端确认仅创建这一个）→ 选择返回新路径 → 导航后未提交名称被丢弃且未产生额外目录
- 移动端布局实测：390px / 360px 下底部三按钮与输入行均无横向溢出
- 全量 1980 测试：1948 通过 / 28 跳过 / 仅 4 个已知 EPERM；tsc / lint 干净
