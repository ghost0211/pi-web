# v0.9.68

> v0.9.67 的桌面安装包构建失败，未发布任何安装包；本版修复该构建错误后重新发版。

## 修复：新增统计路由导致桌面构建失败

v0.9.67 的 `desktop-windows` CI 在 **Build the signed desktop installer** 一步失败：

```
.next/types/app/api/sessions/stats/route.ts#L14
Type 'OmitWithTag<typeof import(".../app/api/sessions/stats/route"), ...>'
does not satisfy the constraint '{ [x: string]: never; }'
```

原因：Next.js 会按路由契约校验路由模块的导出——**只允许导出 HTTP 方法与段配置**。新的家族统计路由额外导出了 `MAX_STATS_SESSIONS` 和一个测试用的解析器注入点。`tsc --noEmit` 看不到这些类型（它们只在构建时生成），所以本地类型检查是干净的。

处理：

- 聚合逻辑移到 `lib/session-family-stats.ts`，用**参数注入**代替模块级测试开关：`collectFamilyStats(requests, resolvePath)`，生产调用走真实会话查找，测试注入固定文件。
- 路由现在只导出 `runtime` 与 `POST`。
- 测试相应拆分：路由测试覆盖来源/内容类型/体积守卫、id 与角色校验、以及“响应不含路径与正文”；新增 lib 测试覆盖聚合、无费用标记、不可读会话，以及 `(path, size, mtime)` 缓存在文件追加后重新解析。

功能行为与 v0.9.67 的发布说明一致，无变化。

## 已知环境限制

本机运行 `next build`（webpack 与 Turbopack 两种模式）都会在读取 `next.config` 之后立即报 `TypeError: generate is not a function`，与本次改动无关（CI 在同一提交上能编译全量代码，只在上述路由导出类型上失败）。因此构建验证以 CI 为准，本地未运行 `next build` 污染开发产物。

## 验证

- 全量 2054 测试：tsc 与 lint 干净；4 个已知 EPERM（Windows 符号链接）仍为既有失败。
- CI：web-ci 与 desktop-windows 均通过后才视为发布成功（安装包、签名与 `desktop-latest.json` 以公网校验结果为准）。
