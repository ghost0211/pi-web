# v0.9.69

> v0.9.68 安装包无法使用：更新后会话列表报 `HTTP 500`。本版修复打包缺失文件并加上构建期守卫后重新发版。

## 修复：桌面安装包缺少 server chunk，导致所有 API 500

v0.9.68 的安装包中，安装版日志显示：

```
Error: Cannot find module './chunks/6429.js'
Require stack:
- server\.next\server\webpack-runtime.js
- server\.next\server\instrumentation.js
...
```

instrumentation 钩子启动时加载失败，`/api/session-management` 返回 500，会话列表无法加载。

排查结论（不是安装损坏，也不是用户配置问题）：

- 逐文件比对公网安装包清单与安装目录：**7234 个文件全部一致**，没有漏拷。
- 用安装包里的产物**新起一个 server**，同样 500、同样报缺 chunk。
- 原因：`copyStandaloneServer()` 只复制了 Next 的 standalone 追踪结果（外加 `.next/static` 与 `public`）。standalone 是 `@vercel/nft` 选出的**子集**，漏掉了一个仅由 instrumentation 在启动时按需导入的异步 chunk。整个构建过程没有任何环节检查 server 的真实模块解析，所以坏包被正常打包并发布。

修复：

- 复制构建产物中**完整的 `.next/server`**，覆盖 standalone 子集，确保 webpack 运行时可能请求的 chunk 都在。
- 校验打包后的 `.next/server` 与构建产物**逐文件一致**（名称与大小），防止将来改复制逻辑又把文件丢掉。
- 在 `tauri build` 之前**真正启动打包后的 server**，请求 `/api/session-management` 并断言 200。静态检查证明不了这件事——追踪子集自身是自洽的，只有启动才能复现。失败时构建直接中止并打印 server 自己的错误输出。

该 smoke 已用 v0.9.68 的坏包验证：能准确复现 `Cannot find module './chunks/6429.js'` 并以非零码失败。

## 升级说明

- 由于 v0.9.68 的 server 无法服务 API，请在更新后**完全退出**旧实例（托盘 → 退出）再启动，或直接运行新安装包覆盖安装。
- 会话文件、配置、凭据均未受影响，无需迁移。

## 验证

- tsc 与 lint 干净；全量测试与既有 4 个 Windows 符号链接 EPERM 保持一致。
- CI：`web-ci` 与 `desktop-windows` 均通过（后者包含新的 server 启动 smoke）后，才以公网安装包、签名与 `desktop-latest.json` 的校验结果视为发布成功。
