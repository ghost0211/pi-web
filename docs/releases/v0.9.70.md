# v0.9.70

> 远程主机目录终于能挂载了；Diff 不再「看起来没效果」；问卷能被模型真正用起来。

## 修复：远程主机「打开」总是报错

现象：RemoteDirPicker 里目录能正常浏览，点「打开」却报
`sshfs failed (code ?, timed out). Check the host credentials with 测试连接 first.`
而「测试连接」是成功的——所以答案从来不在凭据上。

两个叠加的缺陷：

1. **把常驻进程当成一次性命令等待**。`sshfs.exe` 是 FUSE/WinFsp 挂载进程，挂载存在它就一直运行。旧代码 `await` 它退出，于是必然等满 30 秒、判定超时、`kill()`，把刚刚建好的挂载自己拆掉。**任何机器都不可能成功。**
2. **UNC 名字里塞了远程路径**。`\\sshfs.r\user@host\home\me\proj` 会被 Windows 拒绝为
   `System error 67: The network name cannot be found`，看起来像凭据/网络问题，实际是命名限制。正确做法是只映射**主机根**，路径落在盘符内：`Z:\home\me\proj`。

修复：

- 挂载改为 detached 启动 + 轮询盘符判定就绪，只有**失败**的挂载才被杀掉（`startSshfsMount`）。
- 优先使用 UNC 提供程序（无需常驻子进程、无需 stdin 输入密码），仅当主机配置了 `IdentityFile` 时才用 `sshfs.exe`。
- `~/` 与相对路径先解析远端 `$HOME` 再按绝对路径挂载，避免路径中某段是符号链接时映射失效。
- `net use` / `ssh` 的输出按 Windows OEM 代码页（GBK）解码；此前按 UTF-8 解码，`系统错误 67` 会变成乱码。
- 远程目录不存在时明确报「远程目录不存在」，不再重复映射同一主机根并抛出误导性的 `error 64`。

同一台真实主机上的验证（直接调用挂载路由）：

| 场景 | 结果 |
|---|---|
| `/home/chentao/projects/xsport-TV` | 200 → `Z:\home\chentao\projects\xsport-TV`，列目录正确 |
| 再次打开同一路径 | 200，复用已有盘符 |
| `~/projects/xsport-TV` | 200，解析到同一路径 |
| 不存在的目录 | 502，明确指出路径不存在 |

已知限制：需要 `IdentityFile` 的主机仍走 `sshfs.exe`；若系统安全软件干扰 Cygwin 子进程，该路径仍可能失败——但现在会显示 sshfs 自己的错误（例如 `read: Connection reset by peer`），不再是伪装的超时。

## 改进：文件 Diff 为什么「有时没效果」

Diff 来自 `git diff HEAD`，因此：

| 文件状态 | Diff |
|---|---|
| 仓库内新建（untracked） | 全绿 |
| 已跟踪且修改 | 红绿 |
| 与 HEAD 完全一致 / 被 `.gitignore` 忽略 / 不在任何仓库内 / 二进制 / 过大 | 无 diff |

也就是说，问题不在「新建」，而在「是否属于 git 仓库且确有改动」。以前这类情况会静默退回源码视图，看起来像功能坏了；现在接口返回 `reason`，文件查看器直接显示「无差异：不在 git 仓库内」「无差异：与 HEAD 一致」「无差异：被 .gitignore 忽略」等。

## 修复：结构化问卷几乎从不触发

- 模型给出的可选标题在「工具 → wrapper → 面板」链路中被丢弃，面板只能显示兜底标题；现已全程传递。
- 提示词此前只约束「一次问几题」，没有说明**何时**该问。现改为情境触发：当下一步取决于只有用户能做的决定（目标环境、覆盖还是保留数据、按哪套约定）时使用它，而不是自己默默选一个。
- 新增真实 SDK 端到端测试：工具被注册且处于活跃集、调用会产生 `method: "questionnaire"` 请求、回答以工具结果回到同一轮、用户取消仍是「拒绝」而非默认值。

## 修复：任务进度残留「运行中」

「任务进度」展示的是模型最后一次 `todolist` 调用写入的清单。会话早已结束，只要历史里有 `in_progress`，药丸就一直呼吸绿环——把**记录的状态**误当成**当前活动**。现在：

- 会话空闲时，残留项渲染为「未完成」（虚线圆点），不再谎称运行中；
- 真正的运行态只来自 `runningSessionIds` / `agentRunning` / pending 命令，不再从会话记录推断；
- 后台子代理在主会话空闲时仍按服务端运行快照正确显示运行中。

## 修复：Java / Python 子进程中文输出乱码

Windows 上 JVM 以 GBK 写 stdout 时，SDK 按 UTF-8 解码会得到替换字符。现在服务启动时设置 `JAVA_TOOL_OPTIONS`（stdout/stderr 编码）与 `PYTHONIOENCODING=utf-8`，只补缺失项，不覆盖用户显式设置。
