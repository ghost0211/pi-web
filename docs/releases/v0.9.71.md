# v0.9.71

> v0.9.70 的 Linux CI 失败（Windows 通过），本版修复其中的跨平台缺陷并重新发布。功能内容与 v0.9.70 相同。

## v0.9.70 的失败原因

`web-ci` / `desktop-windows` 的 **ubuntu-latest** 测试步骤失败，Windows 通过。原因是新加的挂载测试用了 Windows 专属命令：

- 失败路径用 `taskkill` 结束挂载进程、用 `tasklist` 探测存活；
- 在 Linux 上 `taskkill` 不存在 → 进程没被杀掉 → 管道仍打开 → `node --test` 无法退出（不是断言失败，而是挂住直到作业超时）。

修复：

- `killProcessTree()` 跨平台：Windows 用 `taskkill /T /F`，其他平台按进程组 `SIGKILL`（挂载以 detached 启动，是进程组组长）。
- 失败分支额外 `destroy()` 掉三根管道并 `unref()`，即使杀进程没生效也不会把宿主拖住。
- 测试本身改用可移植的 `process.kill(pid, 0)` 探测存活，不再依赖 `tasklist`。
- GBK 解码断言在缺少 GBK 解码器的 Node 构建（small-icu）上跳过，而不是失败。

已在 **WSL Ubuntu 22.04 + Node 22.19** 上验证受影响的六个测试文件（72 个用例全过，JVM 端到端按平台跳过）。

## v0.9.70 内容（同前）

- **远程主机目录**：不再把常驻的 `sshfs.exe` 当成一次性命令等待（旧代码必然 30 秒超时并杀掉刚建好的挂载）；UNC 只映射主机根，路径落在盘符内（此前塞进 UNC 名字会被 Windows 拒绝为 `error 67`）；`~` 路径先解析远端 `$HOME`；`net use` 输出按 GBK 解码；目录不存在时给出明确错误。已在真实 Ubuntu 主机验证挂载、复用与错误路径。
- **文件 Diff**：接口返回 `reason`，查看器直接说明「不在 git 仓库内 / 与 HEAD 一致 / 被 .gitignore 忽略 / 二进制 / 过大」，不再静默退回源码视图。仓库内新建文件仍是全绿。
- **结构化问卷**：模型给的标题不再在链路中丢失；提示词说明「何时该问」而不只是「问几个」；新增真实 SDK 端到端测试。
- **任务进度**：会话结束后不再把记录里的 `running` 当作正在运行，残留项显示为「未完成」。
- **子进程编码**：Windows 下为 Java/Python 子进程补 UTF-8 默认值，不覆盖用户显式设置。
