# v0.9.72

> 远程主机「打开」仍报错的真正原因：不是挂载失败，而是**接口契约对不上**。v0.9.70/71 修好了挂载后端，但客户端从来没收到能用的响应。

## 现象

挂载提示框底部红字显示 **`HTTP 200`**。这正是问题所在：挂载其实成功了，客户端却把它当失败处理。

## 原因

`POST /api/ssh/mount` 返回 `{ localPath }`，而客户端 `RemoteDirPicker` 要求 `{ ok, mountPoint }`：

```ts
if (!response.ok || !data.ok || !data.mountPoint) {
  throw new Error(`${data.error ?? `HTTP ${response.status}`}`);
}
```

于是 `200` + 没有 `mountPoint` → 抛出 `HTTP 200`，用户看到的错误码其实就是成功码。这个不一致从功能加入起就存在，所以「打开远程项目」从来没有成功过；v0.9.70/71 修的是挂载后端，客户端仍然解析不了。

## 修复

- 新增 `lib/ssh-mount-contract.ts`：**唯一定义** `MountResponse`，以及成功/失败响应的构造函数。
- 路由改为返回 `{ ok: true, driveLetter, mountPoint, remotePath, reused, backend }`，失败返回 `{ ok: false, error, backend? }`——与 `/api/ssh/ls` 的 `ok` 约定一致。
- 客户端改为导入同一类型，不再自己声明一份，避免再次漂移（下次字段改名会直接是类型错误）。
- 增加契约测试：构造函数字段、客户端必须读取 `ok`/`mountPoint`、路由不得再返回 `localPath` 这类私有字段名。
